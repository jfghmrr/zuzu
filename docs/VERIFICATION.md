## Подтверждено

- Сервер: **14 тестов pytest**. Реальный HTTP API через TestClient и временную SQLite БД; для приватных/социальных сценариев создаются независимые аккаунты. Не используются фиктивные успешные ответы сервера.
- Flutter: **5 тестов**, включая узкий экран 320×568 с текстом 150%, границу календарного дня, стабильные ID локальных уведомлений, передачу ошибки/идемпотентного ID и исправленный выход из формы после серверного сохранения.
- `flutter analyze`: **No issues found**.
- `flutter build web --no-web-resources-cdn`: сборка создана. Это web-артефакт для локальной проверки, не iOS/Android релиз.
- Ручной smoke через браузер, viewport 390×844: email DEV-вход, вставка 6 цифр, ограничения/счётчик повторной отправки, серверная/клиентская валидация, создание владельца и питомца вида «Игуана», приблизительный возраст 18 месяцев, свой профиль, переход в ветпаспорт, выбор даты и сохранение ветзаписи, создание связанного напоминания с выбором даты и времени, возврат после сохранения, визуальная проверка загрузки реальных тайлов карты, перезагрузка с восстановлением сессии/профиля. Тестовые данные явно названы тестовыми.

Логи автоматических проверок находятся в `docs/checks/`. В web smoke выявлена ошибка PopScope: запись сохранялась, но форма не закрывалась. Исправлено; regression test проверяет возврат на предыдущий экран без второго подтверждения.

## Что именно проверяют серверные тесты

1. OTP: cooldown, предел неверных попыток, истечение и отсутствие доступа без сессии.
2. Уникальность питомца; невозможность присвоить чужой account_id через профиль.
3. Приватный ветдокумент с изображением: чужой GET записи, список, PUT и прямой URL медиа закрыты.
4. UTC-конвертация напоминания, проверка IANA timezone и формата времени.
5. Пост с двумя фотографиями, повторный запрос с тем же ID, хронологическая лента подписок, уникальная реакция.
6. Комментарий, ответ, жалоба, защищённая очередь модерации, удаление собственного поста и недоступность дочернего контента.
7. Заявка, принятие только получателем, друзья и счётчики; встречный запрос не создаёт вторую дружбу; отмена чужой заявки запрещена.
8. Диалог двух аккаунтов, запрет третьему, идемпотентность сообщения, unread/read.
9. История: просмотр вторым аккаунтом, список только автору, ответ с контекстом, недоступность после expires_at, включая файл.
10. Двусторонняя блокировка: профиль, сообщения и связи; восстановление разрешённого доступа после разблокировки.
11. Карта: bounding box, обсуждение, скрытие модератором и исключение из выдачи.
12. Ограничения текста/медиа, некорректный файл, запрет подмешивания ветвложения в публичный пост, удаление аккаунта/сессии/медиа.
13. Подтверждение второго контакта только исходным аккаунтом, одноразовость кода, повторный вход через этот контакт в тот же аккаунт.
14. Ключевая пагинация без повторов, закрытие комментария к скрытому посту, worker без дублирования внутреннего напоминания, удаление привязки устройства при выходе.

15. Поиск клички кириллицей с другим регистром и ввод служебной категории карты только модератором.

Пункты сгруппированы в 14 тестовых функций. Эта проверка не заменяет нагрузочный аудит, pentest, эксплуатационную проверку PostgreSQL и тесты на реальных устройствах.
