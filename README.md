# ЗуЗу — Flutter + API

Исходники мобильного приложения и локально запускаемого сервера по текстовой спецификации `zuzu-mvp-prompt.md`. Общая кодовая база iOS/Android; Flutter Web используется для доступной проверки интерфейса.

**Статус:** работающая локальная тестовая реализация. Не считать релизом App Store/TestFlight. Figma недоступна подключённому аккаунту: точное совпадение, брендовые ассеты и связи прототипа не подтверждены. Смотрите [отчёт проверок](docs/VERIFICATION.md), [реестр](docs/SCREENS.md), [допущения](docs/DECISIONS.md), [интеграции](docs/INTEGRATIONS.md) и [остаток работ](docs/REMAINING.md).

## Быстрый запуск

Требуются Python 3.11+ и Flutter 3.47.4/Dart 3.13.3. Проверка проведена с Python 3.14. Создавайте виртуальное окружение: системные зависимости не нужны.

```sh
cd server
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
AUTH_MODE=dev APP_ENV=development .venv/bin/uvicorn app:app --host 127.0.0.1 --port 8000
```

API автоматически применяет версионные миграции. Локальные данные хранятся в `server/zuzu.db`, изображения — в `server/private_media`. Повторный запуск сохраняет данные. Не используйте настоящие персональные данные в локальном HTTP-режиме.

Во втором терминале:

```sh
cd mobile
flutter pub get
flutter run -d chrome --web-port 8080 --dart-define=API_URL=http://127.0.0.1:8000
```

Либо соберите статический предпросмотр:

```sh
flutter build web --no-web-resources-cdn
python3 -m http.server 8080 --bind 127.0.0.1 --directory build/web
```

Откройте http://127.0.0.1:8080. В режиме `AUTH_MODE=dev` случайный шестизначный код показан на экране. Никакой доставки SMS/email в этом режиме нет. Создайте два аккаунта на **разных** тестовых контактах в разных профилях браузера/устройствах. Готовых вымышленных публикаций, счётчиков и новостей нет. Для поиска подпишитесь на второй профиль; публикации попадут в хронологическую ленту.

На iOS simulator API_URL — `http://127.0.0.1:8000`; на Android emulator — `http://10.0.2.2:8000`; на реальном телефоне нужен доступный **HTTPS**-сервер. Сервер по умолчанию слушает только loopback.

## PostgreSQL и worker

```sh
cp .env.example .env
# Замените POSTGRES_PASSWORD и прочие нужные значения в .env.
docker compose up --build
```

Секреты остаются в `.env`, который исключён из Git. PostgreSQL не публикует порт наружу. Поднимите HTTPS reverse proxy перед API; задайте ограниченный CORS и лимиты запросов/вложений на proxy. Доступ к БД и volume изображений должен иметь только сервис. План резервных копий, их шифрование и срок удаления из backup должны быть согласованы до production.

Worker создаёт внутренние напоминания, обрабатывает outbox сообщений и удаляет осиротевшие медиа. Локально его можно запустить отдельно с теми же переменными БД/хранилища:

```sh
cd server
AUTH_MODE=dev .venv/bin/python worker.py
# Разовый проход для диагностики:
AUTH_MODE=dev .venv/bin/python worker.py --once
```

Системные напоминания локальные, социальный push — серверный. Worker **не отправляет** push для напоминаний: это исключает двойную доставку на одном устройстве. До 60 ближайших локальных уведомлений, синхронизация при входе, изменении и возврате приложения. После изменений с другого устройства откройте приложение на остальных устройствах для актуализации локального расписания.

## Структура

- `mobile/lib/features/` — auth, profiles, feed, stories, relationships, chat, vet_records, reminders, map, notifications, settings.
- `mobile/lib/core/api.dart` — HTTP, сессия, загрузки, приватный кеш только в RAM.
- `mobile/lib/core/platform_services.dart` — локальные уведомления, FCM, timezone.
- `mobile/lib/core/ru.dart`, `ru.json` — русские статические строки интерфейса. Динамические подписи и даты форматируются в соответствующих виджетах.
- `server/db.py` — SQLAlchemy-схема, индексы и уникальные ограничения.
- `server/app.py` — прикладные операции, валидация и проверки доступа.
- `server/migrations/` — применяемые версии схемы/данных.
- `server/worker.py` — фоновые задачи.
- `server/tests/`, `mobile/test/` — серверные и клиентские проверки.
- `docs/` — продуктовые решения, права, настройка, отчёт.

API-документация доступна по http://127.0.0.1:8000/docs. `Item.kind` объединяет небольшие сущности с общими ACL и жизненным циклом; JSON содержит только проверенные поля. `target` — серверно проверяемая ссылка. Это осознанное упрощение P0, а не разрешение произвольной записи в БД.

## Модерация и обратная связь

Задайте отдельный длинный случайный `ADMIN_KEY` только на сервере. Swagger `/docs` позволяет вызвать `/admin/queue`, `/admin/moderate` и `/admin/map` с заголовком `X-Admin-Key`. Пользовательский токен не даёт этих прав.

Очередь содержит реальные обращения и жалобы. Модератор передаёт ID объекта, `action` (`hide`, `restore`, `resolve`) и обязательную причину. Действия записываются в `moderation_audit`. `/admin/map` принимает `factory`/`construction`, координаты, описание, город и обязательный источник проверки. Обычный пользователь не может создавать эти категории. API доступен в локальной сети только по настройке администратора; для эксплуатации рекомендуются VPN, персональные роли и аудит доступа поверх этого минимального процесса.
